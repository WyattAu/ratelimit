  At `replenished == 0` the taken branch computes
  `(remaining + 0).min(burst)` == `remaining` (remaining <= burst invariant),

- src/sliding_window.rs:57:75 replace `+` with `-` in
  `unwrap_or(now + window)` (SlidingWindowBackend::check)
  The fallback arm is reachable only when the entry deque is empty AND the
  request was denied. Denial with an empty deque requires `limit == 0`
  (count 0 < limit fails only for limit 0), which forces
  `window = interval * burst == 0`; `now + 0` == `now - 0`. Unreachable
  divergence.

- src/sliding_window.rs:44:50 replace `<` with `<=` in the window-eviction
  `while` (SlidingWindowBackend::check)
  Divergence requires a recorded timestamp exactly equal to `window_start`
  (nanosecond `Instant` equality). Practically untestable; eviction of the
  boundary element is semantically negligible (it is the oldest expired
  entry; the count changes by at most one only at that exact instant).
